# Этап 5 DEV — тестовый акт УЗК

Запуск: `Запустить Этап 5 DEV.cmd`. Проверка среды без открытия окна:
`Запустить Этап 5 DEV.cmd CheckOnly`.

Используется установленный Python 3.12 в профиле пользователя; отдельные
зависимости перечислены в `requirements_stage5.txt`. Нужен установленный Excel
для чтения XLS/XLSX. Программа не устанавливает пакеты и не выполняет VBA.

1. Выберите проект и паспорт. Для текущего принятого checkpoint:
   **Гараж Казахстан / 9/2026**.
2. Выберите ВОМ `Гараж казахстан\Паспорт\9 от 06.10.2026\ВОМ отгрузочный счет 183  (5).xls`.
3. Нажмите «Предварительный расчёт». Читаются только видимые строки отгрузки.
4. Проверьте марки и количества. Текущий контроль: 104 строки, 15822.14 кг,
   четыре марки, 33 контролируемые единицы. Отметьте «Марки и количества проверены».
5. Нажмите «Создать ТЕСТ Word». Каждый запуск создаёт отдельную папку
   `DEV\Stage5_Выход\<время>_<идентификатор>`; существующие файлы не заменяются.
6. Нажмите «Открыть Word». Документ содержит явные пометки
   **ТЕСТ / ОБРАЗЕЦ ЗАПОЛНЕНИЯ** и **РЕЗУЛЬТАТЫ КОНТРОЛЯ НЕ ПОДТВЕРЖДЕНЫ**.

Графы обнаруженных дефектов и заключения заполняются точными образцовыми
значениями «ДНО» и «годен» только в TEST для «Гараж Казахстан». Проверяются
SHA десяти прежних актов и все их 56 строк. Отсутствующий, изменённый,
пустой или неоднозначный образец останавливает генерацию. Эти значения
не подтверждают выполнение нового контроля. Официальная выдача не реализована:
для будущего режима нужны фактические результаты и отдельное подтверждение
ответственного исполнителя по каждой марке (исполнитель, время подтверждения,
обе фактические оценки и основание контроля). Общая галочка проверки марок и
количеств таким подтверждением не является. Фамилии,
оборудование, квалификация, сертификаты и незаполненная линия подписи взяты из
first-passport шаблона. Они не являются новой подписью или подтверждением проверки.

Preview и генерация не меняют реестр, не списывают остатки и не закрывают паспорт.
Производственные ВЗМК.xlsx и УЗК.xlsm не открываются. Код этапов 1–4 не изменён.
При смене проекта, паспорта или ВОМ preview сбрасывается. Перед генерацией повторно
проверяются SHA входов и кода. Ошибки checkpoint, количества, профиля, lookup,
правила, массы или шаблона блокируют генерацию и показывают конкретную причину.

Чтение: DEV/ВЗМК_DEV.xlsx, DEV/УЗК_DEV.xlsm, принятый DEV Stage 4 со связанными
JSON, справочник марок выбранного проекта, выбранный ВОМ и точный первый шаблон
УЗК по номеру первого паспорта соответствующего года. Источники открываются
read-only; макросы и обновление ссылок в Excel отключены. ВОМ с внешними
подключениями не поддерживается. Сетевые вызовы Python заблокированы.

Расчёт выполняет принятый `Catalog.lookup` / `calculate_uzk` Stage 4. Stage 5
умножает только длину каждого сегмента на min(количество ВОМ, остаток реестра).
Повторения одной марки в ВОМ суммируются; разные марки не объединяются.
Одинаковые дубликаты реестра не увеличивают остаток, конфликтующие блокируют расчёт.

Формирование акта: одна физическая строка на марку, несколько сегментов —
отдельные строки текста внутри её ячеек. Старые марки, геометрия и PDF-ссылки
удаляются. Прочие части DOCX сохраняются без перепаковки их содержимого.

Прежний проверенный результат и его неизменяемые доказательства находятся в
`validation\stage5_implementation_20261008_105100`. Старый `tests/test_stage5.py`
проверяет тот исторический документ с пустыми графами результатов.
Новый образец, извлечение всех исторических строк, native Word validation и
текущие хеши находятся в `validation\stage5_sample_results_20261008_130441`.
Точечные проверки образца: `tests/test_stage5_sample_results.py` с переменной
`STAGE5_SAMPLE_VALIDATION_DIR`, указывающей на эту новую папку. Отдельный
`check_s5r1.py` в ней повторяет четыре относящиеся к S5-R1 проверки на новых
изолированных fixtures. Полная регрессия этапов 1–4 и повторный пользовательский
E2E после заполнения двух граф не выполнялись. Предыдущий preview E2E принят
по сообщению пользователя.
