ВЗМК — Справочник марок проекта. Этап 3

Запуск: двойной щелчок «Запустить Этап 3.cmd».
Используется существующий Python 3.12, openpyxl и pywin32.
Этапы 1–2 запускаются прежним способом. Их файлы не изменены.

1. Сохраните и закройте ВЗМК.xlsx перед запуском.
2. Выберите проект из списка реестра.
3. Вставьте таблицу из NotebookLM в большое текстовое поле.
4. Нажмите «Проверить импорт». Эта кнопка ничего не записывает.
5. Проверьте строки preview. При необходимости отметьте конкретный конфликт
   или допустимую строку ПРОВЕРИТЬ в столбце «Разрешить».
   Можно выделить строку и нажать кнопку подтверждения или пробел.
6. Нажмите «Применить импорт» и подтвердите применение.
7. Результат покажет количество добавленных, заполненных, изменённых,
   неизменённых, требующих проверки и пропущенных строк, а также backup.

Формат Markdown:
| Марка | Профиль |
|---|---|
| Б4-1 | 20Ш1 |
| К1 | 35Б1 |
| К2 | Гнз120x60x6 |

Поддержан также текст с табуляцией и заголовками Марка и Профиль.
Другие столбцы, пустые значения и неоднозначные дубли требуют исправления входа.
Ошибки во входной таблице блокируют применение всего импорта.

Справочник: Документы\<фактическая папка проекта>\Справочник марок.xlsx.
Один лист «Марки»: Марка | Профиль | Краска | № АКЗ.
Заголовки закреплены, есть автофильтр. Ручные столбцы новой марки пустые.
Краска и № АКЗ заполняются вручную в Excel. Закройте справочник перед импортом.
Кнопка «Открыть справочник марок» открывает существующий файл и не создаёт его.

Статусы:
NEW — новая марка.
FILL — заполнить пустой профиль.
SAME — без изменений, файл не переписывается, если нет других изменений.
CONFLICT — текущий и предложенный профили отличаются; без отметки пропускается.
CHECK_REQUIRED — ПРОВЕРИТЬ. Новая марка или пустой профиль записываются
только с отдельной отметкой. Нормальный профиль никогда не заменяется на ПРОВЕРИТЬ.
ERROR — исправьте входную таблицу и выполните проверку заново.
Одинаковые дубли сводятся к первой строке с предупреждением. Порядок новых марок сохраняется.

Для сравнения используются NFC, регистр, пробелы. В профиле технические x/х/×
сравниваются одинаково между цифрами. Исходная существующая марка не переписывается.
Изменённый профиль хранится в написании подтверждённого импорта.

Безопасность:
ВЗМК.xlsx только читается. Если сохранённый файл изменён после открытия окна,
импорт останавливается; перезапустите окно с новым сохранённым состоянием.
Существующие паспорта не изменяются.
Резервные копии сохраняются в .stage3-backups рядом со справочником.
Для первого создания backup .absent.txt фиксирует отсутствие предыдущего файла.
Для существующего файла backup XLSX побайтово совпадает с исходником.
Перед заменой временный XLSX перечитывается и проверяется.
Все существующие клетки, кроме подтверждённых изменений Профиль, сохраняются
побайтово внутри XML. Остальные части XLSX-пакета сохраняются без изменений.
Неоднозначность существующих марок, папок, другая структура, защита, объединения
или Excel table останавливают импорт. Автоматическая миграция не выполняется.
Отсутствующая папка проекта не создаётся автоматически.

Поиск папок: сначала существующий explicit mapping из settings.json.
Иначе — точное нормализованное имя среди непосредственных дочерних папок
Документы и Документы\ЗАКРЫТЫЕ ОБЪЕКТЫ. Рекурсивного поиска и fuzzy guessing нет.
Один кандидат принимается; несколько кандидатов дают ambiguity STOP.
Невалидный explicit mapping не заменяется автоматическим угадыванием.

Production-аудит после исправления M1: 53 проекта;
AUTO_DIRECT 1, AUTO_ARCHIVE 11, EXPLICIT 1, AMBIGUOUS 0, MISSING 40.
Гараж Казахстан — EXPLICIT; Гранит — AUTO_DIRECT.
Быков, Роксемаш, Теплица, СКФ и Щёкиназот — AUTO_ARCHIVE.
ТЭМПО 1/2 и Ковчег остаются MISSING: требуется explicit mapping пользователя.
При validation реальные справочники и папки проектов не создавались.

NotebookLM используется отдельно. Этот этап не вызывает API и не рассчитывает УЗК.
