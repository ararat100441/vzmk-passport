# Этап 8 — безопасное закрытие и защита данных

Запуск: `Запустить Этап 8 DEV.cmd` (Python 3.12, установленный Microsoft Excel,
`pywin32`, `olefile`; список зависимостей в `stage8_closure/requirements.txt`).
Вызовов AI, API, сети и платных сервисов в программе нет. EXE относится к Этапу 9.

## Разрешённый режим

Этот checkpoint реализует и проверяет закрытие только в изолированном TEST.
Кнопка **«Создать искусственный TEST-стенд»** копирует DEV XLSM в новую папку
`validation/stage8_ui_<дата>_<id>/sandboxes/<uuid>/`, создаёт вымышленные проект,
паспорт `8001/2099`, отгрузку, документы-заглушки JSON и подтверждения контроля.
Исходные TEST/SAMPLE_ONLY документы не используются как подтверждённые результаты.
Сам стенд и его подтверждения явно помечены искусственными. Положительный результат
имеет статус `CLOSED_TEST`, `official_issue=false`.

Паспорт `9/2026` закрывать запрещено, включая его копию внутри стенда. Выбор
`STAGE7_SELECTED_TEST_MANIFEST.json` показывает состав и причину STOP, без запуска
генераторов и без изменения реестров. УЗК SAMPLE_ONLY и АКЗ TEST не подтверждают
фактический контроль. Официального переключателя или автоматического повышения
TEST → OFFICIAL нет. Активация работы с реальными подтверждёнными паспортами
требует отдельного разрешения и проверки адаптера фактических доказательств.

## Закрытие

1. Выбрать точный `inputs/CLOSE_REQUEST.json` своего стенда.
2. Проверить проект, паспорт, отгрузку, весь состав и обязательные документы,
   подтверждённые количества УЗК и остатки до/после.
3. Отметить подтверждение и нажать **«Закрыть паспорт»**. Дополнительное окно
   повторяет данные и по умолчанию выбирает отмену.
4. Программа повторно проверяет SHA запроса, источников и кода, соответствие
   документов проекту/паспорту/отгрузке и подтверждение каждого количества.
5. Под общей Windows-блокировкой создаётся устойчивый журнал намерения; для
   списания создаётся и проверяется побайтная резервная копия XLSM. Ошибка
   резервирования запрещает сохранение и публикацию.
6. Excel с отключёнными VBA, событиями и обновлением ссылок изменяет только
   нужные значения C в отдельной копии. После Save книга нормально открывается
   read-only; проверяются количества, VBA-потоки, формулы, стили и структура.
7. Целевой файл и его путь удерживаются Windows handles без разрешения внешней
   записи/удаления. Проверяются file identity и SHA. Байты проверенной копии
   записываются через тот же handle без снятия блокировки до COMMITTED;
   identity и DACL целевого файла сохраняются. Это не атомарное переименование:
   reader может увидеть частичные байты, а смерть процесса посреди записи —
   оставить непригодный XLSM. Тогда APPLYING/STOP, проверенный backup и запрет
   повторного списания; автоматического восстановления файла нет.
8. Записывается `COMMITTED`. Журнал является отдельным реестром закрытий;
   схема ВЗМК и код Этапов 1–7 не меняются.

Уникальный ключ: нормализованный проект + номер паспорта. Смена имени запроса,
выбор другой отгрузки или повторное открытие не дают повторно списать этот паспорт.
Количество списания равно подтверждённому количеству по каждой обязательной марке,
не общей отгрузке и не длине швов. Отрицательный остаток запрещён. Ноль сохраняется
как ноль; исходная пустая ячейка читается как одно изделие по принятой семантике
Этапа 5. Неоднозначные строки выбранной марки запрещают запись. Если УЗК явно не
требуется, закрытие фиксируется только в журнале; XLSM не сохраняется и не заменяется.

## Журнал, копии и восстановление

`journal/00000000.json` и последующие файлы записываются только добавлением,
с flush/fsync, собственной SHA-печатью, номером последовательности и SHA предыдущего
события. Состояния: `INTENT → BACKUP_VERIFIED → STAGED → APPLYING → COMMITTED`.
Ошибка оставляет операцию незавершённой и блокирует новое закрытие до восстановления.
Программа не повторяет списание автоматически.

Копии: `backups/<operation_id>/УЗК_TEST.xlsm` и `SHA256.json`. Предыдущие копии
не перезаписываются. Журнал связывает их SHA, metadata SHA, preview и протокол Excel.
`transactions/<operation_id>/XLSM_PRESERVATION.json` содержит native-проверку.
Сбой до полной инициализации стенда оставляет диагностическую папку, которая
не может быть использована без корректного `SANDBOX.json`.

Кнопка **«Проверить / восстановить незавершённую операцию»** проверяет цепочку,
копию, file identity и целостность evidence. Она не сохраняет и не заменяет XLSM:

- SHA книги равен «до»: `ABORTED_UNCHANGED`; подготовленная попытка отменяется,
  списания нет. Для новой попытки требуется новый preview и подтверждение.
- Состояние APPLYING и SHA книги точно равен проверенному «после»: только
  дописывается `COMMITTED`, без повторного списания.
- Любое иное состояние, повреждённые копии/журнал/evidence или исчезнувший журнал
  при изменившейся книге: STOP. Автовосстановления «на глаз» нет.
- Смена file identity, даже при прежнем SHA, или старая незавершённая операция
  без identity требуют review: STOP, без автоматического commit/replay.

### Операторское восстановление частичной XLSM

Не заменять файл вручную, не удалять journal/SANDBOX и не редактировать старые
receipts. Ручная замена, даже побайтно верным backup, остаётся неизвестной сменой
identity и приводит к STOP. Для исходного APPLYING разрешено восстановить только
доказанную повреждённую частичную запись с прежней identity, SHA которой отличается
от BEFORE и AFTER. Целая неизвестная книга требует отдельного расследования.

1. Выбрать прежний `inputs/CLOSE_REQUEST.json` в том же изолированном стенде.
   Интерфейс показывает «Обнаружена незавершённая операция», статус, причину,
   точный путь backup, его SHA, реестр и последствия. Закрытие заблокировано.
2. Если доступна кнопка **«Восстановить из резервной копии»**, прочитать сведения
   и нажать её. Отдельное подтверждение по умолчанию выбирает **Нет**. Отмена
   не изменяет книгу или журнал. Недоступная кнопка сопровождается точной причиной STOP.
3. Программа под обязательными Windows handles повторно проверяет журнал,
   BEFORE конкретной операции, принадлежность backup и metadata, пути, исходный
   STAGED/evidence, отсутствие COMMITTED и более поздних закрытий. Проверяет backup
   нормальным read-only открытием Excel, без VBA, событий, ссылок или сохранения.
4. В приватной папке на том же томе создаётся побайтная, flush/fsync проверенная
   копия backup. Native Excel проверяет её до изменения целевого пути. Журнал
   добавляет `RESTORE_PREPARED → RESTORE_APPLYING`, связывая recovery id, старую
   и новую identity, SHA повреждённого файла, backup и verified restored SHA.
5. Повреждённая книга сохраняется как `transactions/<operation>/restore_<id>/damaged.xlsm`.
   Два handle-rename с `ReplaceIfExists=FALSE` переводят её в evidence и публикуют
   целую проверенную книгу. Handles запрещают внешнюю запись/удаление/замену.
   Каталоги удерживаются с FILE_LIST_DIRECTORY, а не только READ_ATTRIBUTES:
   защита имени каталога действует и при отсутствующем дочернем target.
   Directory handles разрешают WRITE sharing для операций с дочерними именами,
   но запрещают DELETE sharing; handles книг запрещают и WRITE, и DELETE sharing.
   Между rename целевое имя кратко отсутствует: внешний creator может занять его,
   но тогда публикация строго STOP, без перезаписи созданного им файла и без fallback.
6. Под удерживаемыми handles проверяются новая identity и точное равенство SHA
   backup. Точная копия восстановленных байтов проходит native Excel normal open;
   evidence связывает результат с target/backup/identity. Только затем добавляется
   `RECOVERED_ABORTED`. Паспорт не CLOSED, списаний **0**. Старые события и receipts
   не переписываются; новая identity разрешена лишь этой цепочкой восстановления.
7. После успешной проверки выбрать запрос заново, выполнить новый preview, проверить
   все входы и отдельно подтвердить новое закрытие. Старый preview недействителен.
   Само восстановление и повторный запуск никогда не повторяют списание.

При смерти процесса во время restore снова выбрать тот же запрос: новый просмотр
проверяет только три заранее записанные формы состояния — старая повреждённая книга
и новая копия; отсутствующий target с обеими книгами в recovery-папке; либо опубликованная
новая книга и повреждённый evidence. Для продолжения требуется новое явное подтверждение.
Любая иная identity/байты, повреждённый backup/журнал/evidence или посторонний файл
в целевом имени дают STOP. До `RECOVERED_ABORTED` никакое закрытие не разрешено.
Сбой копирования в приватный stage не затрагивает target; отдельный rename не публикует
частичные байты. Гарантии относятся к смерти процесса на локальном NTFS, не к потере питания.

Если SHA уже равен AFTER, использовать только проверку журнала: она завершит COMMITTED
без записи книги. Уже COMMITTED операция не восстанавливается из старого backup.
Если SHA равен BEFORE с прежней identity, проверка журнала даёт ABORTED_UNCHANGED.

Для восстановления нужны вся папка стенда, журнал и копии. SHA-цепь обнаруживает
повреждения и случайные изменения, но не является электронной подписью или
защитой от администратора, намеренно переписывающего все доказательства.
Проверены Windows/локальный NTFS и Microsoft Excel 16. Сеть, другие файловые
системы и физическое отключение питания не аттестованы; иные ФС и невозможность
получить обязательные handles дают STOP, без release/reacquire обхода.

Очистка собственного Excel независимо пробует Close и Quit; ошибки и исходный
HRESULT сохраняются в START/END diagnostics с PID/creation time и путём TEST-книги.
Quit может завершить процесс с задержкой. При os._exit finally не гарантирован;
orphan требует проверки ownership/ROT и контролируемого решения. Чужой Excel
программа не завершает. Причина прежнего спонтанного 0x80010108 не установлена.

## CLI

Все команды запускать локальным Python 3.12 с `-B stage8.py`:

```text
fixture --parent validation/stage8_my_test/sandboxes
preview <sandbox>/inputs/CLOSE_REQUEST.json --save-preview <sandbox>/PREVIEW.json
close <sandbox>/PREVIEW.json --confirm "<точная строка confirmation из preview>"
recover <sandbox>
restore-preview <sandbox> --save-preview <sandbox>/RESTORE_PREVIEW.json
restore <sandbox>/RESTORE_PREVIEW.json --confirm "<точная строка confirmation из restore-preview>"
inspect-stage7 <точный STAGE7_SELECTED_TEST_MANIFEST.json>
```

Запросы вне `inputs` стенда, пути через symlink/junction/hardlink и запись в DEV
или рабочие реестры запрещены. CLI close требует точную строку с номером паспорта
и печатью preview. Старый preview после изменения входов или кода недействителен.
