# ВЗМК — Паспортизация металлоконструкций

Личная Windows-программа для автоматизации подготовки паспортов качества и сопроводительных документов металлоконструкций. Актуальная версия исходного кода — **0.9.12** (`stage9_app/__init__.py`).

## Возможности

- Чтение реестра паспортов и отгрузочных ведомостей металлоконструкций (ВОМ).
- Подготовка приложения № 1, документов визуального и измерительного контроля (ВИК), ультразвукового контроля (УЗК), антикоррозионной защиты (АКЗ) и документа о качестве.
- Справочник марок, импорт данных и справочники профилей.
- Предварительная проверка состава, видимых строк, количества, массы и площади.
- Варианты АКЗ № 0–3, настройки и автоматическое формирование тестовых документов АКЗ.
- Отдельные DEV/TEST-стенды, контроль целостности файлов, резервирование, журналирование и восстановление операций.
- Графический интерфейс и командные точки входа для отдельных этапов.

## Технологии

Python 3.12, Tkinter, openpyxl, pywin32 и Windows COM Automation для Microsoft Excel и Word; lxml для XML-документов. Существующие конфигурации PyInstaller сохранены в `*.spec`. Программа выполняет обработку локально.

## Запуск из исходного кода

Требуются Windows, Python 3.12 с Tkinter, установленные настольные Microsoft Excel и Microsoft Word с поддержкой COM, а также Windows PowerShell.

В PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements_stage5.txt olefile
.\.venv\Scripts\python.exe stage9.py
```

Для раннего интерфейса этапа 1 используется `main.py`. Точки входа этапов 2–8: `stage2.py` … `stage8.py`; их порядок работы описан в существующих `STAGE*_README*` и `STAGE*_DEV*`.

Перед формированием документов подготовьте входные реестры, ВОМ и принятые шаблоны. `settings.json` содержит относительные пути к папке документов, реестру и шаблону первого паспорта; их необходимо согласовать с вашим расположением данных. Часть источников в исходной установке находится **за пределами каталога Pasport** и не входит в этот репозиторий. Само скачивание исходников не создаёт рабочий комплект производственных данных.

В интерфейсе этапа 9 создайте отдельный DEV-стенд из подготовленных источников или откройте существующий. Формирование выполняйте после предварительной проверки. Привязки источников и контрольные SHA в программе сохранены; произвольная замена шаблонов может остановить проверку.

## Состав проекта

| Каталог | Назначение |
| --- | --- |
| `passport_app` | Этапы 1–3: реестр, приложение, ВИК и каталог марок |
| `profiles_stage4` | Этап 4: справочник профилей |
| `uzk_stage5` | Этап 5: УЗК |
| `akz_stage6` | Этап 6: АКЗ |
| `stage7_quality` | Этап 7: документ о качестве |
| `stage8_closure` | Этап 8: закрытие и восстановление |
| `stage9_app` | Этап 9: общий интерфейс и управление DEV/TEST-стендом |
| `DEV` | Существующие DEV-реестры, справочники и тестовые входные файлы |
| `tests`, `e2e_user_stage*`, `validation` | Исходники проверок и пользовательских сценариев |

Имеющиеся шаблоны и тестовые входы внутри проекта сохранены. `.gitignore` исключает секреты, виртуальные окружения, кэш, зависимости Node.js, временные данные, резервные копии, результаты локальных прогонов и готовые EXE-сборки. Файлы сборочных настроек `*.spec` включены.

## Стадия разработки

Версия **0.9.12**, стадия **DEV/TEST**. Исходники этапов 1–9 сохранены. Тестовые документы и данные SAMPLE_ONLY не подтверждают фактический контроль и не разрешают официальную выдачу паспортов. Для производственной эксплуатации требуется отдельная приёмка с фактическими данными.

При публикации на GitHub дополнительные аудит, review, полный цикл тестирования и новая сборка EXE не выполняются.
