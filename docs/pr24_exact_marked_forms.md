# PR24 — ВИК и УЗК: только выделенные поля первого паспорта

## Окончательное пользовательское правило

Первый паспорт выбранного объекта — точный образец текста, таблиц и оформления.
Меняются только отмеченные жёлтым переменные поля, плюс номер и даты
из соответствующих СТОЛБЦОВ реестра ВЗМК.xlsx. Не вводить новые кнопки
и не перестраивать таблицы. Оригиналы не редактировать.

### ВИК — 1_2026 - ВИК.docx

- В одном DOCX два акта. Word-поля PASSPORT_NO повторяются 2 раза;
  VIK_DATE — 2 раза. Новый номер N/2026, второй номер N/2026-1;
  обе даты ВИК — из ВЗМК.xlsx.
- На второй странице единственная жёлтая переменная: исходное
  «Колонна, Пластина монтажная, Шайба, Элемент монтажный».
  Она стоит между неизменными текстами «НШ, ТШ, СШ соединения »
  и « МП в соответствии».
- Вместо неё — уникальные НАИМЕНОВАНИЯ изделий из текущей
  видимой ВОМ; для четырёх проверочных марок — «Балка».
  Не писать в ВИК отдельные номера марок Бп2-1, Бп2-5 и т.д.
- Оставить невыделенные формулировки, фамилии, удостоверения,
  две страницы, поля подписей и стили первого паспорта.

### УЗК — 1_2026 - УЗК.docx

- Заголовок «Акт № ... от ...»: номер паспорта и дата УЗК
  берутся из соответствующих данных нового паспорта в реестре.
- В оригинале первые 5 строк таблицы — шапка, дальше марки.
- Для каждой марки с положительным планом УЗК заменить только
  исходную марку, L×S, дату, частоту и угол. Плановое количество
  изделий — из общего УЗК.xlsm, состав — из видимой ВОМ.
- Не дублировать одну марку на каждое изделие.
- Геометрия по принятому Stage4 Профили.xlsx; между марками
  длины не суммировать. Пример [16П, УЗК 8 шт.:
  стенка L=1280х5 мм, полки L=1024х8,4 мм.
- ФИО, клейма, приборы, таблица исполнителя, стиль, колонки
  результатов, дефектов и заключений сохраняются как в первом
  документе; допустимость их применения к новой отгрузке
  остаётся на подтверждении перед официальным выпуском.
- На исходных марках есть старые внешние hyperlinks на К1-5.pdf
  и другие чужие чертежи. При копировании строк удалять
  ссылки на старые чертежи, оставляя видимый стиль марки.
- Жёлтую подсветку у заменённых полей убрать только в новой копии.

## Что внесено в исходники

- production_app/highlighted_reference.py копирует исходный DOCX
  строго в НОВЫЙ файл, сверяет SHA, проверяет структуру,
  адресно заменяет поля и сохраняет исходную сетку Word.
- production_app/core.py активирует геометрию только для
  распознанного первого УЗК либо ранее выбранного режима.
- production_app/office.py использует точные формы первого
  паспорта, только когда их структура распознана, затем добавляет
  существующую черновую пометку и выполняет штатную цепочку.
  Для иных форм прежний генератор остаётся без изменений.
- requirements.txt включает python-docx, сборка Windows нужна
  отдельно. Персональные DOCX не публиковались на GitHub.

## Разделение черновика и официального выпуска

Перенесённые по желанию пользователя «ДНО», «годен» и
сведения персонала НЕ становятся автоматически доказанными
результатами новой отгрузки. Пока текущий контроль не подтверждён,
результат остаётся черновиком; официальный release не обходится.
