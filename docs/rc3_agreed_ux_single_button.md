# RC3 — согласованные изменения интерфейса (25.10.2026)

## Строго ограниченный объём

Пользователь сам определяет, какие кнопки и поля убрать. В этой ветке реализуются только замечания из последней проверки экрана «Фактические результаты» и главных четырёх кнопок. Существующие механизмы Word/Excel/PDF, проверка хешей, защитный сценарий COM, readback и recovery не удаляются.

## Что теперь видит пользователь

- Главный экран RC3: вместо четырёх последовательных кнопок одна **«Сформировать пакет»**.
- Внутри выполняется CHECK → PREPARE → VERIFY, после чего автоматически создаётся и открывается **ЧЕРНОВОЙ PDF** из подготовленных документов. Этот PDF расположен исключительно в частной папке текущей операции и помечен «ЧЕРНОВИК». Текущий рабочий реестр ещё не изменён.
- Пользователь один раз подтверждает **точные** проект, номер, дату, путь реестра, путь папки результата и то, что просмотрел все документы; после этого выполняются CONFIRM → RELEASE → COMMIT → READBACK → COMPLETE.
- При отказе на просмотре ничего не пишется в рабочий реестр, предварительный PDF остаётся доступен; та же кнопка становится «Просмотреть и подтвердить». После исправления введённых фактов требуется новый CHECK, а не повторная запись старых данных.
- Ошибка любого внутреннего шага показывается через штатный диалог, а не через четыре неработающие кнопки.

## Экран «Фактические результаты»

- Убрана верхняя строка «Ответственный / Начало / Окончание / ВИК / УЗК / АКЗ».
- Ненужный ручной ввод имени ответственного отключён. Утверждения фактического контроля и полномочий на выпуск, а также отдельный просмотр PDF не удалены. В утверждённые шаблоны **не копируется** ФИО из старых актов — токен `RESPONSIBLE` остаётся пустым, а не заполненным ложной подписью.
- Даты существующего паспорта читаются из **его точной строки** реестра ВЗМК. Для нового паспорта дата окончания предварительно предлагается как текущая дата компьютера **с показом и подтверждением на финальном экране**, а остальные даты должны получаться из формул новой строки в временной копии реестра. Программа **НЕ берёт** фиксированные контрольные даты из первого исторического паспорта; если подтверждённых формул нет — STOP с названием поля. Для такого проекта пока остаётся вопрос источника новой даты, а не повод выдумать её.
- Из справочника **только выбранного проекта** по точным маркам ВОМ автоматически подставляются профиль, краска и № АКЗ. Пустое назначение остаётся пустым; `0` — реальный вариант АКЗ №0. SHA источника закреплена. В окне «Шаблоны объекта» показан автоподключённый справочник из реальной папки проекта.
- Для АКЗ показаны **только фактически используемые варианты**; если утверждённый вариант у проекта единственный и назначения пока не подтверждены, виден его пустой блок, **но отметка №0 в марки не подставляется**. Количество слоёв определяется по рабочему шаблону, а не по номеру варианта.
- Пользователь вводит **диапазоны фактических текущих измерений** климата и сухой толщины слоя — `От`/`До`. По согласованному правилу центральное значение рассчитывается как **(От+До)/2**, с фиксацией источника диапазонов и проверки на изменение. Это именно арифметическая середина диапазона, не статистическая средняя всех наблюдений и не допустимый нормативный интервал.
- Для однослойного «Гараж Казахстан» нет двенадцати строк трёхслойной окраски. Двухслойные акты со специальной методикой сейчас останавливаются до подтверждения их расчёта; программа не делает вид, что этот режим уже проверен.
- Сохранены обязательные подтверждения результатов испытаний, форм и приложенные первичные протоколы. **ВОМ не подтверждает факт выполненного ВИК/УЗК/АКЗ сама по себе.** Программа не создаёт `ГОДЕН`, даты испытаний, измерения или подписи без текущих источников.

## Защитные проверки

- Временный черновой PDF снабжается SHA-256 и проверяется перед подтверждением и перед записью.
- Автокопирование источников первого паспорта, выбор только по своему проекту и корректный парсер ВОМ сохраняются из PR16/PR17.
- Рабочая RC3-interface на компьютере пользователя и реальный `ВЗМК.xlsx` не изменялись: эта ветка пока содержит только **исходники GitHub и unit-тесты**.
- Вызовы Windows MS Word/Excel и весь цикл собранного EXE после исправлений **ещё не выполнены**. PASS Python-модулей не является разрешением выпускать реальный паспорт.

## Windows acceptance одним заданием

1. На ноутбуке найти точный локальный worktree, на основе которого создана последняя `C:\VZMK-Passport\1.0.0-RC3-autofirst`. Не заменять его целиком GitHub-версией: выбрать необходимые коммиты `fix/rc3-agreed-ux` с сохранением последнего локального движка.
2. Убедиться, что новых кнопок не появилось: одна главная кнопка. В фактических результатах нет верхней строки, выбранный проект «Гараж Казахстан» показывает только АКЗ №0 с одним слоем; его назначения подставлены строго из собственного справочника, если он содержит реальные назначения.
3. Проверить реальную ВОМ **104 марки / 288 изделий / 15 822,14 кг / 1 021,644 м²**. Следующий номер реестра **11/2026**.
4. Проверить дату нового паспорта в временной копии: если контрольная дата не вычисляется в реестре, получить конкретный STOP и показать пользователю, какая дата и из какого столбца отсутствует. Не подменять её старой датой и не блокировать независимую проверку Приложения №1.
5. Отдельно проверить сценарий с синтетическими подтверждёнными тестовыми данными в изолированной копии реестра, предварительный PDF и отказ от подтверждения: **ни одной строки записи**. Затем явное подтверждение: полный COM E2E, сводный PDF, readback и recovery, визуальный просмотр страниц.
6. Запустить всю существующую Windows-регрессию одним запуском; исправлять обычные ошибки в текущей копии без нового пользовательского задания, но останавливаться при риске оригиналам/изменении методики/неподтверждённых первичных данных.
7. Только при PASS собрать **отдельный** EXE и ярлык, не заменяя RC3 и `1.0.0-RC3-autofirst`. Пользователь затем самостоятельно оценит экран и продолжит замечания.

**Текущий статус:** Python source checks PASS; native Windows E2E и новая поставка EXE — NOT_RUN. Нельзя объявлять готовый Windows-релиз до этих проверок.
