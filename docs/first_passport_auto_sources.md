# Автоматический поиск первого паспорта проекта

## Что изменено

При выборе проекта (например, «Гараж Казахстан») программа использует данные **его** первой строки в реестре. Папка проекта ищется внутри заданного пользователем корня «Работа/Документы» с учётом регистра, но **только по точному имени проекта**. Если папок две или они отличаются опасным образом — STOP; файлы других проектов не используются.

В найденной папке `Паспорт` автоматически обнаруживаются исходники номера `1/2026`:

| Роль | Файл первого паспорта для «Гараж Казахстан» |
|---|---|
| Приложение №1 | `1_2026 - Приложение № 1.xlsx` |
| ВИК | `1_2026 - ВИК.docx` |
| УЗК | `1_2026 - УЗК.docx` |
| Документ о качестве | `1_2026 - Документ о качестве.docx` |
| Приложение АКЗ №0 | `1_2026 - Приложение к АКЗ.xlsx` |
| АКЗ №0 (особое имя) | `Акт № 4-2026.xlsx`, **только** если внутри E4 указан номер первого паспорта `1/2026` |
| Справочник (при наличии) | `Гараж казахстан/Справочник марок.xlsx` |

Для проектов с номером первого паспорта `1/1/2026` используется префикс `1_1_2026`; серии не смешиваются. Поиск не использует произвольные похожие имена, поздние паспорта, папки других объектов и общие шаблоны без подтверждения.

### Что загружается автоматически

1. Источники первого паспорта читаются **только для просмотра, сравнения структуры и фиксации SHA-256**.
2. **Приложение №1** автоматически берётся из точного исходного XLSX первого паспорта: это уже поддерживаемый и независимо проверяемый режим штатного генератора, который полностью заменяет марки и итоги по новой ВОМ в отдельной копии.
3. ВИК, УЗК, документ о качестве и АКЗ первого паспорта содержат исторические результаты, партии ЛКМ, заключения, подписантов и даты. Они остаются **образцами оформления**. Генератор продолжает использовать привязанные проекту **очищенные, утверждённые рабочие формы**. Оригиналы **нельзя** передавать в генератор как пустые шаблоны: это переносит чужие старые результаты в новый паспорт.
4. Список автоматически найденных первых документов выводится в журнал при выборе проекта. В окне «Шаблоны объекта» первая исходная Excel-форма отображается как автоматически выбранный путь (без кнопки изменения). Остальные пути обозначают очищенные рабочие формы, а не исторические оригиналы.

## Никаких изменений в источниках

- Первые паспорта, реестр, ВОМ, подписанные Word/Excel **не изменяются**.
- Исходные SHA-256 добавлены к защите операции CHECK→PREPARE. Если исходник изменился — STOP.
- Кэш конфигурации `settings.json` не переписывается во время просмотра первого паспорта; автоматический режим включается при выборе проекта в новом GUI.
- Рабочий Excel-реестр изменяется только отдельной подтверждённой операцией выпуска, без новых обходов.
- Существующий механизм Word/Excel/PDF, проверка числовых данных и откат не переписаны.

## Проверка локальных исходников

Запусти из папки проекта в Windows:

```powershell
py -3.12 -B tools/check_first_passport.py --registry "<рабочий реестр, путь>" --documents "<Работа/Документы>" --project "Гараж Казахстан"
```

Это **read-only** проверка автопоиска, ничего не выпускает и не записывает.

## Текущий технический предел

Данная ветка исправляет **автоматическое нахождение первого паспорта** и **выбор первого Приложения №1**. Она **не утверждает**, что из заполненного старого ВИК/УЗК/качества/АКЗ уже можно безопасно, автоматически и без подтверждения сформировать пустые рабочие формы для всех других объектов. Для полной автоматизации на новом объекте нужен отдельно проверенный преобразователь его исторических заполненных форм в чистые, который не перенесёт старые результаты. Нельзя скрывать этот предел успешными тестами поиска.

Локальная Windows-интеграция выполнена поверх действующей RC3-interface `19302d7`, без отката более поздних генераторов и исправления ВОМ. Отдельная поставка предназначена для `C:\VZMK-Passport\1.0.0-RC3-autofirst`. Её настройки сохраняются в `rc3-autofirst-settings.json`, отдельно от `rc3-ui-settings.json` прежней сборки. Очищенные формы продолжают читаться из `RC3-interface\Templates`; архив первых паспортов задан отдельным `first_passport_documents`. Результаты фактических Windows-проверок находятся в папке `Acceptance` поставки.

## Приёмка

1. В изолированной копии рабочего реестра выбрать «Гараж Казахстан», проверить подсказку `1/2026` и следующий `11/2026`.
2. Сверить путь каждой автоматически найденной первой формы и её SHA-256; не допускать документов `2/2026` или из другого объекта.
3. Выбрать прежнюю настоящую отгрузочную ВОМ: 104 марки, 288 изделий, 15 822,14 кг, 1 021,644 м².
4. Приложение №1 должно формироваться из оригинального первого приложения, сохраняя шапку и печать и подставляя данные **новой ВОМ**.
5. При вводе достоверных текущих фактов допускается штатный учебный E2E с Word/Excel/PDF **только на отдельной копии**, без официальной выдачи. Старые результаты контроля не переносить.
6. Предыдущие EXE 1.0.0 и RC3-interface не заменять до пользовательской приёмки. Кнопки по требованию пользователя пока **не удалять**.
