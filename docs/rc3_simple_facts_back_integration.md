# RC3 — интеграция PR21 и максимально простое окно фактических результатов

## Пользовательский сценарий

**Один выбранный проект → одна ВОМ → Фактические результаты → ← Назад → Сформировать пакет.**
Новый экран фактических результатов содержит ТОЛЬКО таблицу
Марка / Профиль / № АКЗ / УЗК шт. и необходимые для выбранных
вариантов АКЗ интервалы климата/толщины. Точка росы автоматически
рассчитывается по Магнусу. При необходимости сохраняются 3 слоя и
специфические параметры 3-слойной формы внутри блока АКЗ.

Ниже блока климата больше нет отдельных таблиц сварных соединений,
дополнительных полей документов, приложений протоколов, трёх
галочек подтверждения или кнопки отдельного сохранения.
Кнопки «Заключения текущего контроля» и «Обновить назначения
из справочника» также отсутствуют.

Внизу окна всегда видна **← Назад**. Нажатие, Escape и закрытие
крестиком сохраняют ВВЕДЁННЫЕ значения в текущую оперативную
заявку. Разрешены частично заполненные диапазоны.
Если пользователь находился внутри редактируемой ячейки марки,
редактор сначала явно фиксирует последний ввод.
Программа возвращается на главный экран без записи в реестр
ВЗМК и без выпуска паспорта. При повторном открытии сохранённые
в этой сессии диапазоны и марки восстановлены.

Кнопка «Создать учебную копию» убрана из настроек, но само
изолированное тестирование и backup/recovery остаются в движке.

## Порядок проверки и выпуска

После нажатия «Сформировать пакет» программа:
1. Преобразует сохранённые диапазоны в фактические числовые
   значения (воздух/поверхность/влажность, толщина слоя, точка росы).
2. Проверяет соответствие марок и количества УЗК по общей ведомости
   и точность формул, реестра, дат и источников.
3. При наличии всех достоверных фактов формирует черновые документы
   Word/Excel и предварительный PDF, не меняя реестр.
4. Открывает PDF и запрашивает ОДНО ЯВНОЕ подтверждение просмотра
   страниц, достоверности фактов, полномочий и действующих форм.
5. Только после положительного ответа выполняет штатный выпуск,
   commit/readback, backup и recovery в случае ошибок.

Данные, введённые через ← Назад, НИКОГДА не получают статус
«подтверждены» автоматически. При выпуске отсутствие реального
результата ВИК/УЗК, протоколов, сведений утверждённых форм или
действительных дат приводит к конкретной блокировке. Программа
не создаёт вымышленные заключения «ГОДЕН», старые результаты
первого паспорта или придуманные даты.

**Важно:** после удаления пользовательских полей некоторые первичные
подтверждения нельзя внести через ежедневный экран. Это остаётся
ограничением для официального реального выпуска, пока такие
текущие сведения не доступны из утверждённых внешних источников.
Изменение интерфейса само по себе НЕ решает этот источник данных.

## Правило даты из PR21

Дата начала во всех паспортах одного проекта — из даты начала
ПЕРВОГО паспорта. Для «Гараж Казахстан» первый 1/2026, строка
353, H353 фиксированная дата допустима. Никакой формулы для H353
не требуется. Новая строка проверяется на совпадение даты начала
с первым паспортом. ВИК/УЗК/АКЗ новые контрольные даты не
переносятся автоматически из старых результатов.

## Windows acceptance — одно задание

1. Интегрировать ВЕСЬ PR21 + этот PR в самые свежие локальные
   исходники установленного `1.0.0-RC3-screen-test`, не откатывая
   правки и генераторы.
2. Полная Windows-регрессия одним запуском: 0 FAIL/ERROR.
3. GUI проверить на реальной 4-марочной ВОМ: 4 марки, 11 изделий,
   масса 511.98 кг, площадь 19.533 м², план УЗК 8 шт.
4. Проверить, что «← Назад» работает с пустыми и частичными
   диапазонами, сохраняет активную редактируемую ячейку, возвращает
   и повторно показывает значения, не меняя реестр.
5. Ветка с 104 марками: 288 изделий, 15 822.14 кг, 1 021.644 м²,
   план УЗК 33 шт. — независимая контрольная сверка.
6. Подтвердить чтение H353 из РЕАЛЬНОГО реестра read-only,
   образование новой строки только в копии, правильные даты
   и отсутствие ложных положительных результатов контроля.
7. На изолированной копии с явно синтетическими учебными
   сведениями выполнить нативный Office GUI→Word/Excel→PDF→
   отмена (нет записи), одобрение→commit/readback→recovery;
   проверить страницы, SHA и сохранность старых EXE/реестров.
8. Если что-то не работает — исправить в рамках одного задания;
   не обходить проверку достоверности и не подставлять ГОДЕН.
9. Только после PASS собрать отдельный onedir EXE:
   `C:\VZMK-Passport\1.0.0-RC3-updated`.
   Старые EXE и рабочие реестры НЕ перезаписывать.
   Новых ярлыков на рабочем столе НЕ создавать.

Native Windows Office и новый EXE этой ветки пока NOT_RUN.
Кроссплатформенные тесты не заменяют Windows-приёмку.
