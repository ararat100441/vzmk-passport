# ВЗМК RC3 — фактическая структура 6 исторических форм (19.10.2026)

Изучены шесть переданных пользователем документов **первого исторического паспорта** объекта. Исходные бинарные файлы **не публикуются** в репозитории и не считаются утверждёнными пустыми шаблонами. Записи ниже — только структурная карта для реализации.

## Word

| Форма | Структура | Контракт заполнения |
| --- | --- | --- |
| ВИК | 2 страницы; **два акта в одном DOCX**; 8 таблиц; 11 Content Controls | В документе два PASSPORT_NO и два VIK_DATE, а также DOGOVOR_NO, KMD_CODE, STEEL_MARK и четыре подписных элемента DATE_CTRL / DATE_HEAD. Все исходные реквизиты и результаты заполнены. |
| УЗК | 5 страниц; основная таблица на 45 строк; 2 таблицы в документе | По каждому сварному соединению нужны марка, характеристика/толщина/длина шва, исполнитель и клеймо, дата контроля, рабочая частота, угол ввода, оценка дефекта, заключение. Режим RC3 знает только марку, количество, общий результат, основание. |
| Документ о качестве | 2 страницы; основная таблица 56 строк + блок подписи | Нет Content Controls: основные реквизиты, материалы, данные АКЗ, ссылки на акты и подписанты вписаны как текст. Требуется локальная копия с утверждёнными переменными полями. |

В существующем ВИК таблицы результатов по маркам нет: он ссылается на приложение и первичные документы. Поэтому в новых **утверждённых** формах {{VIK_TABLE}} разрешён, но **не обязателен**. При его отсутствии engine не должен добавлять неутверждённую таблицу. Результаты ВИК и первичные протоколы остаются обязательными входными данными для рабочего режима.

## Excel

| Форма | Структура | Контракт |
| --- | --- | --- |
| Приложение №1 | Лист «Приложение №1», A1:G45. Строки 1–4 шапка, 5–44 фактические марки, 45 «Итого». | Действующий собственный шаблон приложения поддерживается штатной функцией генерации. |
| Приложение АКЗ | Лист «Приложение АКЗ», A1:G44. Строки 1–3 шапка, 4–43 марки, 44 «Итого». | Новая совместимая **копия**: A4={{AKZ_MARKS}}, A5=«Итого», остальные исходные марки удалены; dynamic akz_rows() добавляет строки и итоговые SUM. Сохранение области печати проверить в Windows Excel. |
| Акт АКЗ (3 слоя) | Лист «4», A1:M240; 119 объединённых диапазонов; существенные данные в E, H, J | E4 — номер, H4 — дата акта (числовая Excel); H4 участвует в формулах. E/H/J строки 18–34 — разные фактические материалы, партии, дата/время, мокрая/сухая толщина и климат по каждому слою. E39–E42 — измерительные приборы; 46–50 — подписанты. Нельзя размножать один «climate» на три слоя. |

Контрольный исторический пример содержит 40 строк марок и 42 единицы; повторы марок сохраняются. Это иллюстрация **структуры**, не источник для нового паспорта.

## Что нельзя делать автоматически

1. Не считать заполненные подписанные документы пустыми формами.
2. Не переносить старые даты, названия ЛКМ, номера партий, измерения, приборы, сотрудников и заключения.
3. Не подменять 3 независимых послойных набора АКЗ одним климатическим набором.
4. Не заменять исторический акт УЗК общей таблицей из пяти колонок и не заявлять совпадение с формой.
5. Не изменять рабочий реестр, исходные Word/XLSX или существующие паспорта.
6. Не выпускать рабочий комплект до проверки в Word/Excel на Windows, согласования форм и подтверждения фактических входов.

## Реализовано в ветке feature/rc3-word-controls

- Нативное чтение пустых Word Content Controls.
- Маппинг реальных тегов PASSPORT_NO→NUMBER, DOGOVOR_NO→CONTRACT, KMD_CODE→CIPHER, STEEL_MARK→STEEL; VIK_DATE обрабатывается напрямую.
- Запрет перезаписи ранее заполненных полей.
- Необязательный {{VIK_TABLE}} при обязательных реквизитах, ответственном и EVIDENCE.

## Осталось для последующих этапов

- Подготовить и согласовать очищенный собственный ВИК с реквизитами/подписями, которые подтверждаются ответственным.
- Реализовать строковую модель фактического УЗК с длинами, толщинами, сварщиками, частотой/углом и протоколами; динамически сохранять 8-колоночный макет.
- Реализовать отдельную модель замеров **по каждому слою** АКЗ и typed Excel dates, сохранив формулы и layout исторического 3-слойного акта.
- На отдельной копии качества привязать реквизиты, материалы, реальные ссылки на акты и ответственного (не переносить заполненные старые сведения).
- Проверить шаблон приложения АКЗ в нативном Excel; библиотеки импорта/экспорта могут не сохранить принтерные настройки.
- Финальная приёмка только на копиях, затем отдельное разрешение на реальный выпуск.

Отгрузочная ВОМ и первичные результаты конкретного следующего паспорта требуются **для его оформления**, а не для написания универсального движка.
