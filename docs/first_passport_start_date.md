# ВЗМК — дата начала изготовления во всех паспортах проекта

## Утверждённое пользовательское правило (25.10.2026)

**Дата начала изготовления одна и та же во всех паспортах одного проекта.**
Её следует брать из первого паспорта проекта, из точной первой
строки этого проекта в реестре ВЗМК.xlsx, а не рассчитывать заново.

Для проекта «Гараж Казахстан» первый паспорт — 1/2026, строка 353;
столбец H353 (START_DATE) — правильный фиксированный источник
даты начала для следующего 11/2026. Формула в H353 НЕ требуется.
Точное значение даты программа читает из Excel; не угадывает по дате
окончания первого паспорта и не берёт дату соседнего проекта.

## Что не меняется

- Дата окончания нового паспорта остаётся предложенной датой выпуска
  из создаваемой в отдельной копии строки реестра и показывается
  для подтверждения пользователя.
- ВИК/УЗК/АКЗ даты нового выпуска рассчитываются или читаются
  по своим подтверждённым формулам и источникам новой строки;
  фиксированные старые результаты контроля первого паспорта
  не переносятся в новую отгрузку.
- Если в исходной первой строке START_DATE отсутствует или это
  не дата Excel, программа останавливается с конкретным сообщением.
- Если в подготовленной копии строка нового паспорта получила
  другую дату начала, чем первый паспорт проекта, — STOP.
- Реестр, существующие паспорта, Word/Excel источники, УЗК.xlsm
  и установленные EXE не изменяются на этом этапе.

## Исполнение

`production_app/registry_dates.py` теперь отделяет фиксированную
дату начала первого паспорта от дат фактического контроля.
Новый паспорт создаётся штатным движком сначала в приватной
копии реестра с SHA-проверкой. Уже существующие защитные
проверки, PDF, подтверждение перед записью и восстановление
сохраняются.

Тесты покрывают фиксированный H353, чтение правильного проекта,
отсутствие H353, запрет перепутанной даты в новой копии реестра
и сохранность SHA исходного реестра.

## Windows-приёмка

Один запуск в отдельном рабочем каталоге с актуальным EXE-источником:

1. Чтение настоящего ВЗМК (2).xlsx только для чтения,
   проект «Гараж Казахстан», первый 1/2026, следующий 11/2026;
   H353 принимается как фиксированная дата без требования формулы.
2. На копии реестра подготовить строку 11/2026 с START_DATE
   точно равной H353. Сверить формулы контрольных дат и первичные
   результаты: если их нет, выдавать конкретный STOP, не замалчивать.
3. Сравнить SHA рабочего реестра и исторических документов до/после.
4. Проверить сокращённую ВОМ (4 марки / 11 изделий / УЗК 8),
   полную (104 марки / 288 изделий / УЗК 33), и существующие
   учебные сценарии Word/Excel/PDF и recovery.
5. Сборка нового EXE допустима только после полной Windows-регрессии;
   существующую версию RC3-screen-test не заменять.

**Важно:** этот PR исправляет источник даты НАЧАЛА, но не заполняет
неподтверждённые результаты контроля и не утверждает новые формы.
Отдельные блокеры по другим датам или актам всё ещё возможны.

Native Windows Microsoft Office/GUI не проверялись через GitHub.
