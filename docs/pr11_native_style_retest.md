# PR11 Gate A — использовать встроенные форматы исходного Excel

## Причина предыдущих FAIL

PR10: NumberFormatLocal 'дд.мм.гггг' показывал 19.00.2026.
PR11: NumberFormat 'dd.mm.yyyy' показывал буквальное dd.mm.yyyy;
альтернативный вариант тоже не распознавался.
При этом AKZ_DATE записывалась правильно числом 46314.

Исходный файл '1_1. Акт АКЗ (3 cлоя) 7004.xlsx' проверен по OOXML только для чтения:
- H4 (дата акта): builtin numFmtId=14;
- E22/H22/J22 (даты нанесения): builtin numFmtId=14;
- E23/H23/J23 (время нанесения): builtin numFmtId=20.

## Решение PR12

Не применять никакие NumberFormat/NumberFormatLocal маски при генерации дат/времени.
В предварительно согласованном XLSX-шаблоне уже присутствует встроенный
формат Microsoft Excel. Меняется только Value2 (число/доля суток).
Сохраняются исходные NumberFormat и NumberFormatLocal, после подстановки
проверяется фактическое отображение .Text. Если оно неверно — STOP.
Отсутствие подходящего формата у новой формы — проблема формы, а не
повод записать текст вместо числа либо вписать произвольный код.
Для времени допускается 8:00 вместо 08:00 как эквивалентная нативная
запись того же значения. Буквальное hh:mm или 19.00.2026 запрещены.

## Gate A в Windows (ИЗМЕНЁН)

Создать отдельный worktree от точного commit PR12.
Найти ТОЧНЫЙ исторический исходный XLSX из PR9/PR10, а не однослойный
кандидат и не генерируемый документ. Указывать путь явно:

    py -3.12 -B tests/production/verify_ru_excel_com.py --format-source "<путь к оригиналу 1_1. Акт АКЗ (3 cлоя) 7004.xlsx>"

Проверка ОТКРЫВАЕТ оригинал только на чтение и копирует
в отдельную СИНТЕТИЧЕСКУЮ книгу только native formatting:
- H4 builtin ID14 → A1/A2 (даты),
- E23 builtin ID20 → A3/A4 (время).

Далее тест заполняет синтетические числовые значения, проверяет
19.10.2026 и реальные значения 08:00/10:30, расчёт двух формул,
выполняет Save, Close, ReadOnly Open и повторную проверку.
По окончании временная книга удаляется, SHA оригинала сверяется.
Если формат не прошёл — STOP, получить точную диагностику формата
и отображения; НЕ ПОДБИРАТЬ ВРУЧНУЮ новые маски.

## Далее при PASS

затем Office E2E CHECK → PREPARE → VERIFY → CONFIRM → RELEASE →
COMMIT → READBACK → COMPLETE на изолированной копии реестра.

Повторная сверка SHA, отсутствие осиротевших процессов Office.
