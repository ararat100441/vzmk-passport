# ВЗМК — рабочий режим без DEV-стенда (требования, согласовано 18.10.2026)

## Решение пользователя

Нужна самостоятельная локальная Windows-программа для ежедневной работы инженера ПТО, без Codex при эксплуатации и без необходимости создавать DEV-стенд. В интерфейсе пользователь сам выбирает **рабочий реестр ВЗМК.xlsx**, папку **Работа/Документы**, объект, отгрузочную **ВОМ**, папку сохранения и режим нового паспорта. После проверки и подтверждения программа **добавляет новый паспорт в основной реестр**, с резервной копией и безопасным откатом. Создание официальных актов только по подтверждённым фактическим данным, без «ТЕСТ» значений и подмен.

Код до реализации рабочей версии хранится в `feature/multi-project-devtest`. Релиз 0.9.16 и ветка `checkpoint/0.9.16-devtest` **не изменяются**. Существующий DEV/TEST режим и его тесты не удалять, а оставить доступными для разработчика.

## 1. UX: единое окно, минимум действий

- При первом запуске: выбрать **файл рабочего реестра** (`ВЗМК.xlsx`), корень **рабочих документов**, **папку сохранения**; проверить пути на существование/права/файлы. Конфигурация сохраняется локально и редактируется в «Настройки». Никогда не выбирать рабочие пути за пользователя молча; отображать **полные конечные пути** перед записью.
- Главное окно: объект из **актуального рабочего реестра**, № существующего или следующего паспорта, отгрузочная ВОМ, варианты АКЗ по реальной привязке, папка результата. Действия: **«Проверить данные» → «Подготовить документы» → «Проверить комплект» → «Подтвердить выпуск и запись в реестр»**. Кнопки последующих шагов неактивны до PASS предыдущих.
- При новом паспорте автоматически предложить следующий номер в рамках реальной серии проекта; пользователь видит договор, заказчика, шифры, даты, количества, массу и варианты АКЗ.
- Для существующего паспорта контрольный прогон **не добавляет строку** в реестр, не изменяет подписанные оригиналы; документ в рабочую папку нельзя записать поверх существующего комплекта.
- Каждый результат Word/Excel в **отдельной новой папке** `<папка объекта>/Паспорт/<номер с безопасными разделителями> от ДД.ММ.ГГГГ`; никогда не перезаписывать существующий каталог. Файлы остаются DOCX/XLSX, PDF автоматически не нужен.
- «Отказ/Назад» в любой момент не меняет основной реестр. Повторный клик/параллельный запуск не создаёт дубли.

## 2. Источники и проекты

- Поддерживать отдельно **«Гараж Казахстан»**, **«ТЭМПО 1»** и далее другие имена из реестра (не смешивать с «ТЭМПО 2»). Данные проекта берутся из его собственных утверждённых источников — не из Казахстана.
- Поддерживать **обе схемы номера** `N/YYYY` и `N/S/YYYY`; `1/1/2026`, `2/1/2026` — **верные** номера ТЭМПО 1. Сохранять серию `/1/` неизменной, не приводить к `1/2026` и не допускать смешивания серий/годов. Номер и путь имени файла корректно экранировать, не заменяя исходный номер в теле документа.
- Сверить реальный рабочий реестр перед реализацией: в копии `DEV/ВЗМК_DEV.xlsx` есть подозрительная строка 401 `ТЭМПО 1 | 10/2026` с реквизитами Казахстана; **не считать её достоверной** и **не исправлять автоматически**. При конфликте STOP с понятным объяснением; запросить пользователя для решения.
- Для каждого проекта собственные каталоги первого паспорта, приложение №1, ВИК, УЗК, документ о качестве, шаблоны АКЗ №0–3, профили и назначение марок. Привязка конкретных файлов только после проверки существования и структуры, с их контрольными суммами. Общие шаблоны разрешены только при **явном выборе и совпадении структуры**, не по названию.
- **«Справочник марок.xlsx» у ТЭМПО 1 отсутствует** (подтверждено пользователем). Программа может **создать его отдельный черновик из реальной ВОМ** с маркой, наименованием и количеством. Профиль, краска и вариант АКЗ — только из подтверждённых данных/ввода пользователя. Никогда автоматически не приписывать марке №АКЗ=0. Не выпускать АКЗ, пока необходимые привязки не утверждены.
- УЗК: реестр фактического количества/профилей/швов, аттестованные источники. Сведения `SAMPLE_ONLY` или из TEST-актов не считать результатами контроля. Фактические результаты требуют ввода/подтверждения ответственным исполнителем.
- АКЗ: температура воздуха/поверхности, влажность, точка росы, толщины/материал и даты — реальные подтверждённые данные. Не переносить модельный климат из TEST. Если критические данные отсутствуют, печатать только явно маркированный черновик и **не разрешать официальный выпуск**.
- Сохранять утверждённые правила: порядок и повтор марок, динамические приложения (7/32/100/200), итоги жирным без пустых строк, `E/G` формат с 2 знаками **без изменения значений**, уникальные «Соединения», вычисляемые даты ВИК, УЗК по принятым количествам, акты АКЗ по выбранным вариантам, отсутствие неверных фактов.

## 3. Безопасная запись в ОСНОВНОЙ реестр после подтверждения

- Изначально только чтение реестра/исходников. **Не выполнять никакой записи** при выборе папок, проверке данных, подготовке, предварительном просмотре или ошибке.
- Для *нового* паспорта готовить **в частной рабочей копии**: проектную запись и 100% комплект Word/Excel, все расчёты, реквизиты и ссылки.
- Перед финальным подтверждением сверить полную исходную SHA-256, дату и актуальное состояние реестра, отсутствие дубля номера/занятой папки, доступность Office и отсутствие чужого процесса редактирования. Проверить закрытие принадлежащих приложению Word/Excel, не закрывать пользовательские процессы. Перечислить все пути, изменения и резервные копии.
- После **отдельного явного согласия пользователя в самом приложении**: сохранить версионированную резервную копию неизменённого реестра, журнал операции с идентификатором, обеспечить исключительный доступ; перенести подготовленные документы в **новый** каталог и безопасно применить изменения в реестр (сохраняя формулы, формат, Excel-таблицу, область печати, структуру). Никаких замен существующих комплектов. Механизм crash recovery / компенсационного отката при частичном завершении; не затирать параллельные пользовательские изменения. При ошибке STOP и предложить восстановление из резервной копии с проверкой хэша.
- После операции повторно открыть реестр через Excel, проверить формулы и единственную новую строку, значения массы/даты/соединений, формирование Word/Excel и журнал. **Только тогда** статус `ГОТОВО`. Не называть успехом результат при непросмотренных документах и непроверенном состоянии реестра.
- Официальная выдача **не допускается** при TEST/SAMPLE_ONLY/неподтверждённых результатах, независимо от пользовательского клика. После соответствующей проверки полных фактических данных и полномочий ответственных лиц разрешить собственный production-flow. Никаких фиктивных подписей, поверок или замеров.
- При первом запуске новой production EXE пользователь должен подтвердить реальный рабочий реестр; **никогда не использовать DEV/ВЗМК_DEV.xlsx автоматически**.

## 4. Проверки приёмки и выпуск

1. Сохранить/запустить без изменений `0.9.16` Kazakhstan E2E в изолированной тестовой среде: 104 марки, 288 изделий, 15 822,14 кг, 6 физических файлов, 7 записей, Office cleanup PASS.
2. ТЭМПО 1: прочесть реальные источники, сохранить **`1/1/2026`**, проверить нумерацию и сопоставление шаблонов; реальная ВОМ для существующего паспорта — сравнение с уже оформленными документами.
3. Отдельно проверить реакцию при отсутствии справочника марок (создать черновик без ложных АКЗ-назначений), отсутствии УЗК/АКЗ результатов (официальная выдача запрещена), конфликте строки 401 (STOP без записи), отсутствии шаблонов (STOP).
4. Тест полного подтверждённого сценария нового паспорта — только **на рабочей копии реестра и файлов**: PREPARE/VERIFY → backup → confirm → commit → verify. Протестировать неверный хэш, дубли номера/папки, заблокированный Excel, сбой в середине записи, откат, повторный запуск, работу другого экземпляра Excel.
5. Только после PASS целевых Windows Office E2E и проверки реальных данных собирать **отдельную** рабочую EXE (семейство версий `1.0.0`); `0.9.16` сохранить, новую по умолчанию **не направлять на реальные исходники до приёмки**.
6. Реальный рабочий реестр **не менять в ходе разработки и тестов**. Первый реальный коммит паспорта возможен только по явному подтверждению в новом GUI после обязательных PASS.

## Границы

Stability > Correctness > Convenience > Speed. Не проводить полный рефакторинг, не включать сеть/облако, не публиковать рабочие документы в публичном GitHub, не менять исходники 0.9.16, не скрывать ошибки Office и не обещать production PASS без Windows проверки.
