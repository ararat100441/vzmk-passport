# Адресная правка readback после записи (GPT-6)

Основа: `codex/review-production-r14-final-codex50`, commit `74f6bcf7d76f001e8edbd8c13f1e3403ede42ca2`.

## Наблюдаемая ошибка

В рабочем r14-final CODEX50-r2 после записи трёх Excel возникло
`Hardlink недопустим: .../.vzmk-operations/<id>/backup-registry.xlsx`.
Истинная причина временного значения NumberOfLinks остаётся неизвестной.
Ранее аналогичная ошибка возникала на journal.json и участниках транзакции.

## Изменения

- `production_app/core.py`: только на стадии `NEEDS_READBACK` после
  сверки подписанного журнала/плана, точных путей, ролей, контрольных сумм
  и подтверждения разрешено читать связанные read-only артефакты через
  `post_commit_path`: план, проверенные резервные копии трёх участников,
  `ISSUE.json` и проверенные документы. Точный SHA по-прежнему обязателен.
- `production_app/coordinated.py`: при нативной проверке УЗК резервная
  XLSM-книга читается в том же post-commit-режиме **только после** проверки
  её роли, пути и SHA в `post_commit_context`.
- Добавлены Windows-тесты на настоящие вторые NTFS hardlink для backup,
  plan/ISSUE/PDF и XLSM, на повреждённый SHA и reparse, а также на COMPLETE.

До записи, при повторном выпуске и штатном восстановлении `safe()` остаётся
строгим. Защита от symlink/junction/reparse и native-ошибок сохранена.
Никакие рабочие файлы владельца этим коммитом не менялись. Формы/GUI
и бизнес-логика выпуска не изменены.

## Обязательная приёмка до рабочего использования

1. Выполнить адресные тесты `test_codex46.py`, `test_codex50.py`,
   `test_gpt6_postcommit_artifacts.py` на Windows с pywin32.
2. На изолированных копиях пройти GUI → PDF → запись трёх DEV-файлов →
   native readback → COMPLETE; проверить повторное открытие и pending=0.
3. Рабочую операцию `90428cb148c940e59aa8115893babe43` (уточнить точный
   ID по journal.json на ноутбуке) оставить без изменений до отдельной
   проверки SHA и подтверждения владельца. **Не выполнять автоматический
   rollback / readback / COMPLETE.**
4. Только после проверки собрать отдельный onedir EXE. Эта GitHub-ветка
   является патчем исходников, а не уже готовой рабочей версией.

Windows-E2E для этого патча здесь не выполнялся. Статус: PATCHED / NOT ACCEPTED.
