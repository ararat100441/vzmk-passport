# ВЗМК — автоматические переменные части актов ВИК и УЗК

## Рабочее правило пользователя

Оформление ВИК и УЗК остаётся таким же, как в первом паспорте
выбранного проекта. В ВИК меняются марки из текущей видимой ВОМ,
номер и даты; остальные согласованные постоянные реквизиты/оформление
сохраняются в утверждённых рабочих формах проекта.
В УЗК динамически меняются марка и характеристика соединения;
количество изделий для УЗК берётся из общего УЗК.xlsm.
Не требуются CSV и отдельная большая таблица в GUI.

## Реализовано в исходниках

- production_app/automatic_acts.py: принимает текущую ВОМ,
  плановые количества УЗК и профиль по марке; читает только
  проверенный Профили.xlsx модели Stage4; использует ровно
  существующие принятые правила длины и толщины соединений;
  не суммирует длины разных марок и не удваивает повторяющиеся
  строки марки в ВОМ (плановое число приходит из общего УЗК.xlsm).
- Для видимых марок ВИК генерируется последовательность
  уникальных наименований из текущей ВОМ без старых марок.
- Word подготовленные формы при наличии полей VIK_MARKS и
  UZK_DESIGN получат соответствующие значения автоматически.
  Шрифты, таблицы и остальное оформление остаются шаблонными.
- production_app/core.py: вычисляет и пинит SHA Профили.xlsx
  только для явно адаптированной формы с маркером UZK_DESIGN
  либо при отдельно включённом режиме auto_uzk_characteristics.
  Это сохраняет поведение всех прежних утверждённых форм и тестов.
- tools/inspect_automatic_acts.py: read-only Windows проверка
  реальной видимой ВОМ и двух справочников, печатает отчёт
  расчёта без открытия и сохранения официального реестра.

## Проверенный расчёт синтетического примера

Профиль [16П / ГОСТ 8240-97 при УЗК 8 шт:
- стенка: S=5 мм, L=1280 мм (160 мм на изделие ×8);
- полки: S=8,4 мм, L=1024 мм (2×64 мм ×8);
- частота 5 МГц, угол 70° по ранее принятой Stage4 методике.

Это **расчёт проектной геометрии**, НЕ заключение о фактическом
контроле и НЕ подтверждение пригодности толщины под конкретную
методику/прибор. Применимость к нужному диапазону контроля
уточняется при технической приёмке; значения не объединять
между марками.

## Безопасность

Не копировать из первого паспорта старые результаты ГОДЕН,
дефекты, ФИО сварщиков/подписантов, акты или первичные протоколы.
Оформление и постоянные технические реквизиты можно переносить
только из подготовленной утверждённой рабочей формы.
Недостающий профиль или неоднозначность ГОСТ/размеров — STOP.
Отсутствующий Профили.xlsx также STOP только в новом режиме;
никакого скрытого DEV fallback для рабочего выпуска нет.
Не подключать необследованный Профили.xlsx к рабочему выпуску.

## Чего ещё не сделано

Точная конвертация пользовательского заполненного первого УЗК
с восемью колонками в чистую динамическую форму и постоянные
поля ВИК требуют проверки **реальных** первых DOCX на Windows.
В текущих установленной программе/форме могут отсутствовать
маркеры VIK_MARKS/UZK_DESIGN; данный PR не утверждает, что
конечные акты уже сформированы автоматически во всех объектах.
Утверждение фактических результатов текущего контроля остаётся
отдельным обязательным условием официального выпуска.

## Windows-приёмка в одном задании

1. Найти последние локальные исходники установленной версии
   1.0.0-RC3-updated. Не использовать устаревшую Github-версию
   для отката генераторов Word/Excel/PDF.
2. Прочесть только для анализа оригинальные 1_2026 - ВИК.docx
   и 1_2026 - УЗК.docx Гараж Казахстан: структуру, марки,
   реквизиты, формулировки, фактические результаты, подписи.
3. Подготовить отдельные безопасные очищенные копии только
   меняющихся полей, сохранив исходный вид таблиц и страниц;
   оригиналы НЕ редактировать. Если замены невозможны однозначно
   — конкретно сообщить блокер вместо угадывания.
4. Найти только утверждённый справочник геометрии Профили.xlsx;
   подтвердить ГОСТ 16П и принятые правила Stage4; сохранить
   SHA и использовать внутренний источник без новой кнопки.
5. На реальной сокращённой ВОМ — 4 марки, УЗК 8 — сверить
   автоматический расчёт для [16П и реальные строки первого
   УЗК; требуемый вариант печати и диапазон толщины не угадывать.
6. Подготовить новый DOCX ВИК и DOCX УЗК и PDF на копиях;
   сохранить постоянные поля и текущие марки/характеристики.
   Неподтверждённые факты НЕ объявлять выполненным контролем.
7. Провести полный Windows regression + штатный учебный Office
   E2E, проверить SHA источников, независимый GUI запуск.
8. После PASS собрать новый отдельный EXE, не заменяя
   существующий 1.0.0-RC3-updated, реестр и оригиналы.

Кодовые кроссплатформенные тесты PASS; native Office E2E и
новый EXE для этого изменения ещё не выполнялись.
