# CODEX46 / r14: readback после подтверждённой транзакции

В r13 после успешной записи трёх Excel readback периодически останавливался на повторной проверке числа hardlink. r14 реализует согласованную политику: до записи safe() по-прежнему строго блокирует hardlink, symlink и reparse; после записи для точных участников подтверждённой транзакции число hardlink повторно не является условием отказа.

Исключение ограничено фазой NEEDS_READBACK. Проверяются seal журнала и плана, их расположение и ID, точные пути и роли участников, связь кандидатов с prepared.json, подтверждение и SHA verified.json, резервные копии и candidate SHA. Reparse и ошибки native metadata остаются блокирующими. Readback выполняет Microsoft Excel, проверки строки реестра, отгрузок, остатков справочника, общего УЗК, документов и PDF. При COMPLETE сохраняются mutex, блокировки файлов и повторная сверка candidate SHA. Восстановление и все вызовы до записи используют строгий режим по умолчанию. Повторная запись запрещена прежними source SHA и журналом.

Изменены только storage.py, core.py, coordinated.py и shared_uzk.py. GUI, ВИК, УЗК, АКЗ, генераторы документов и шаблоны не менялись. Новый тестовый модуль test_codex46.py проверяет границы исключения.

Проверки на Windows / Python 3.12 / Microsoft Office:

- 668 регрессионных тестов: PASS, 0 ошибок, 0 пропусков; 15 новых адресных тестов.
- На точных копиях трёх реальных исходных Excel каждый настоящий hardlink до записи дал STOP без записи.
- Исходный код и затем собранный EXE независимо прошли цикл до COMPLETE. Повторный native readback при реальных links=2 после записи прошёл; подмена SHA дала STOP до запуска Excel.
- Обычные single-name файлы: повторный commit остановлен исходным SHA, участники не переписаны.
- Полный frozen GUI: ввод ВОМ, Word/Excel, 8-страничный PDF, явное DEV-подтверждение, три DEV-файла, readback, COMPLETE.
- Независимая сверка: одна новая строка, B и прежняя история F+ сохранены, остатки и УЗК соответствуют кандидату; резервные копии и VBA проверены.
- Все 8 страниц просмотренного и итогового PDF совпали по позиционированным символам и пикселям основного содержимого. На странице АКЗ изменён порядок извлечения символов из PDF-потока при одинаковых символах, координатах и изображении.
- Из 1270 защищённых файлов 1268 совпали по SHA, размеру и mtime. Пользователь подтвердил сохранение двух рабочих Excel во время паузы; их новые SHA зарегистрированы отдельно, они не откатывались. Проверены 39 запросов: все участники записи находятся в изолированных испытательных папках. Журнал действующей незавершённой операции не изменён; завершение и откат не выполнялись. r13 сохранена.

Границы: это приёмка согласованного изменения на DEV-копиях, не выпуск реального паспорта. Причина исторического кратковременного links>1 не объявляется доказанной. Внешний Adobe выдаёт Font Capture 0xc06d007e; PDF проверен независимым Poppler. Унаследованное обезличивание четырёх исторических runtime-модулей сохраняется: 110/114 входов приватной сборки совпадают с публичным снимком. Все четыре изменённых runtime-модуля опубликованы без преобразований. Полная воспроизводимость EXE только из обезличенной ветки не заявляется.
