# УТВЕРЖДЁННЫЙ ДИЗАЙН — ВЗМК-Паспортизация

Статус: **DESIGN APPROVED / NOT IMPLEMENTED**.

Утверждение владельца: 03.11.2026. Источник согласования — концептуальный макет
в чате проекта ВЗМК. Это только спецификация внешнего оформления;
ни один исходник программы, установленный EXE, Excel-реестр или рабочая
операция здесь не изменяются.

## 1. Визуальный стиль

- Направление: строгая профессиональная инженерная программа, светлая тема,
  тёмно-синие акценты, без иллюстраций, градиентов и анимации.
- Базовые цвета: основной фон #F7F9FC, поверхности #FFFFFF,
  первичный акцент #183B63, основной текст #182A3A,
  второстепенный #64748B, границы #D9E1EA.
  Цвета — проектные ориентиры, допускается адаптация к системной теме Windows
  с обязательной читаемостью.
- Шрифт: системный Segoe UI. Заголовок 17–18 pt, заголовки разделов 11–12 pt,
  основной текст 10–11 pt, мелкие пояснения 9 pt.
- Отступы: единый модуль 8 px; между разделами 16–20 px;
  внутри контейнера 12–16 px.
- Группы имеют ровные границы, умеренные скругления там, где их поддерживает
  технология интерфейса, без визуальных эффектов, требующих новых зависимостей.

## 2. Структура основного окна

### Верхняя панель
Слева компактный знак здания/металлоконструкций и надпись:
**ВЗМК — Паспорта металлоконструкций**.
Справа существующая команда «Настройки путей».

### Раздел 01 — Данные паспорта
Компактное расположение существующих полей:
- Объект из реестра.
- Номер паспорта / новый паспорт.
- Исходный паспорт (образец документов).
- Дата окончания / отгрузки.

Никакие значения не подставляются из демонстрационного макета.

### Раздел 02 — Отгрузочная ведомость
Существующая команда «Отгрузочная ВОМ». Под ней/рядом читаемая сводка:
- число марок;
- число изделий;
- масса (кг);
- площадь (м²).

Значения должны отображаться **из существующего расчёта**, не вычисляться
новым альтернативным алгоритмом. Если площадь не задана, не показывать 0.

### Раздел 03 — Документы и контроль
Две уже существующие команды:
- «Фактические результаты»;
- «Открыть документы».

Не добавлять кнопок. Не изменять внутренние формы, таблицы, порядок
проверок и данные фактического контроля.

### Основная команда
Одна широкая тёмно-синяя кнопка «Сформировать пакет» с контрастным белым
текстом. Состояния: доступно / недоступно / идёт выполнение.
Не запускать один выпуск дважды и не разрешать второе подтверждение.

### Журнал операций
Существующий текстовый журнал, оформленный компактным разделом с названием
«Журнал операций»; сохранены все диагностические сообщения и прокрутка.
Ошибки отличаются от информационных сообщений не только цветом, но и текстом.

## 3. Пределы изменений при последующем внедрении

Разрешены только оформление и расположение **существующих** элементов
основного GUI. Не разрешены изменения:
- логики check/prepare/verify/confirm/release/commit/readback/complete;
- источников Word/Excel, расчёта УЗК и АКЗ;
- БД/реестров, файловых путей, форматов документов;
- проверки SHA, обработки Hardlink, резервного копирования и восстановления;
- структуры данных, алгоритмов, зависимостей и сборочной конфигурации;
- текстов заявлений о выполненном контроле и согласований;
- доступности действий, которые сейчас запрещены программой.

Сохраняется **однократное явное подтверждение** перед официальной записью,
если это предусмотрено принятой рабочей логикой.
Внешний вид не должен скрывать предупреждения или фактические ошибки.

## 4. Доступность и совместимость

- Удобно на типичном Windows-экране 1366×768 и более крупном.
- При масштабировании Windows 125–150% поля, кнопки и основной текст не должны
  обрезаться; для малых экранов допускается прокрутка.
- Хороший контраст, видимый фокус клавиатуры, логичный порядок Tab,
  без значений, обозначенных только цветом.
- Использовать имеющиеся возможности tkinter/ttk: **не добавлять**
  UI-фреймворки или сторонние библиотеки исключительно ради красоты.

## 5. Приёмка внедрения

Проверяется после отдельного разрешения владельца на GUI-правки.
Требуемое сравнение: тот же набор существующих органов управления и
те же значения, команды и события при разной визуальной композиции.
Перед рабочим выпуском: запуск на Windows, ручная проверка 100% и 150%
масштабирования, подтверждение неизменности поведения.

**Текущее действие:** утверждён только дизайн. Изменение исходного GUI-кода
и сборка нового EXE пока не производились. Это позволяет реализовывать внешний
вид отдельно от устранения ошибок производственной логики.
