## Охват проверки

В исходном снимке было 383 отслеживаемых файла, из них 322 Python.
Проверены основные модули production_app, важные части passport_app и
жизненный цикл: check → prepare → verify → confirm → release → commit →
readback → complete, восстановление, компенсация, SHA, создание PDF и УЗК.
Проведён статический поиск потенциально опасных шаблонов по рабочим модулям.
Это не доказательство отсутствия дефектов в каждом из 322 файлов.

Базовая ветка уже включала отдельные изменения: обход повторного временного
Hardlink только для проверенных SHA-артефактов после записи; отмена
предварительного PDF по просьбе владельца при сохранении одного явного
подтверждения и создания финального PDF. Эти изменения всё ещё
требуют полного Windows-тестирования.

## Измерения (синтетика, не производственная скорость)

Локальный Linux/Python 3.13, а не Windows/Microsoft Office:

- Файл 32 MiB: SHA старого и нового алгоритма идентичен. tracemalloc:
  предыдущий метод выделял ~32.0 MiB, потоковый ~0.26 MiB.
- Внутренний поиск УЗК, 6 000 строк и 300 марок: 0.236 с до,
  0.001 с после; обе версии нашли 1 800 совпадений. Весь Excel/Word
  не измерялся.
- В 250 000 случайных диапазонах совпали результаты старого и нового
  вычисления границ и сдвигов после удаления строк.

Добавлены 7 адресных тестов в tests/production/test_gpt6_audit.py.
В родительской ветке есть отдельные тесты Hardlink и прямого выпуска.
Они ещё не выполнялись в Windows на новом срезе исходников.

## Оставшиеся риски

1. В production_app/office.py обработчик UsedRange.SpecialCells(-4123,16)
   перехватывает все COM-исключения. Обычное отсутствие найденных ячеек
   тоже может вызвать исключение, но другие ошибки могут остаться
   незамеченными. Без реального Windows Excel нельзя безопасно
   выделить только ожидаемое исключение, поэтому код не менялся.
2. Истинная причина временных вторых Hardlink в Windows неизвестна.
   Базовый обход ограничен подтверждённым post-commit контекстом
   и обязательно должен пройти повторный native readback.
3. Без Windows Office нельзя подтвердить финальные PDF-страницы,
   сохранность оформления и макросов в полной системе.
4. Внешняя ошибка Adobe Font Capture не устранена и не доказана
   как дефект генератора.
5. Последнюю незавершённую рабочую операцию с ID
   90428cb148c940e59aa8115893babe43 перед новым выпуском надо
   проверить по журналу и SHA. Никакой автоматический rollback
   этим аудитом не запускался.
6. Четыре исторических runtime-модуля опубликованы обезличенными;
   полная воспроизводимость EXE только из публичного снимка
   не гарантирована.

## Приёмка перед установкой на рабочем ноутбуке

На Windows/Python 3.12 с установленными зависимостями в изолированном
DEV-профиле выполнить:

    python -m unittest discover -s tests/production -p "test_gpt6_*.py" -v

После адресных регрессий CODEX46/49/50 выполнить полный frozen GUI DEV:
реальная ВОМ → проверка Word/Excel → одно подтверждение без
предварительного PDF → финальный PDF → три DEV-реестра → native
readback → COMPLETE. Перезапустить EXE и проверить отсутствие
незавершённых операций. Отдельно проверить STOP на неправильном SHA,
hardlink до записи, пустых измерениях, отрицательных остатках,
повторном номере паспорта и отказе от подтверждения.

**Заключение:** патчи небольшие, доказанные по исходному коду;
улучшения памяти и сложности подтверждены независимыми микротестами.
Общая производительность и готовность Windows EXE пока не подтверждены.
