# RC3 — единый пакет исправления интерфейса и климата АКЗ

## Утверждённые изменения после просмотра окна пользователем

Главный экран: оставить «Фактические результаты» и «Открыть документы»;
убрать кнопку «Черновик справочника». «Восстановление после сбоя»
перенести внутрь «Настроек путей»; recovery, SHA и откат не удалять.
«Открыть документы» открывает последнюю выпускную папку, а до
завершения — подготовленные черновики, если они имеются.

В таблице текущих марок четыре столбца:
**Марка | Профиль | № АКЗ | УЗК, шт**.
Профиль и № АКЗ привязываются по справочнику выбранного проекта;
количество УЗК — строго из одного общего УЗК.xlsm для этой марки.
Пустой АКЗ не превращается в нулевой, а число УЗК не редактируется.
Отдельные пять колонок «Краска», «Результат УЗК»,
«Основание/протокол УЗК», «Результат ВИК», «Протокол ВИК»
убраны из ежедневного экрана. Код сохраняет ранее подтверждённые
внутренние значения и текущую краску из выбранного справочника,
но **не присваивает ГОДЕН автоматически**. Реальные результаты
контроля/протоколы остаются обязательными для официальной выдачи.

В АКЗ одно лишнее поле «Протоколов АКЗ №0» и его отдельная
кнопка «Приложить протокол АКЗ» удалены. Сохраняется **одна**
общая кнопка первичных документов. Файл может быть связан с
конкретным вариантом АКЗ только после явного подтверждения
оператора; файл ВИК/УЗК не становится протоколом АКЗ сам по себе.

## Климатический расчёт

Пользователь вводит текущие измеренные интервалы «от–до»
температуры воздуха и поверхности, влажности, толщины слоя.
Отдельная ручная строка точки росы удалена.
Среднее воздуха/поверхности/влажности = арифметическая середина
каждого измеренного диапазона.
Точка росы T_d рассчитывается по формуле Магнуса:
gamma = ln(RH/100) + 17.62*T/(243.12+T);
T_d = 243.12*gamma/(17.62-gamma), до 0.1 °C.
Используются средняя температура воздуха T и средняя RH в %.
RH должна быть больше 0% и не более 100%.

Проверяются два независимых условия:
1) средняя температура воздуха строго выше средней температуры поверхности;
2) поверхность как минимум на 3 °C выше рассчитанной точки росы.
Обе проверки выполняются в UI при вводе диапазонов и повторно
в независимой модели перед выпуском. Отдельная ручная подмена
точки росы в производственных данных блокируется.

Толщина слоя продолжает рассчитываться по согласованной
середине фактического диапазона. Для многослойного подтверждённого
АКЗ сохраняется нарастающий итог; данные первого паспорта
не подставляются в новые фактические измерения.

## Безопасность и важные нерешённые условия

ВЗМК.xlsx, УЗК.xlsm, ВОМ, оригиналы первых паспортов и
установленные EXE не изменяются этой GitHub-веткой.
В полной 1.0.0 по-прежнему требуются фактические первичные
результаты ВИК/УЗК/АКЗ и утверждённые формы. Удаление колонок
не является согласием на автоматическую выдачу ГОДЕН.

Проблема даты начала нового паспорта для «Гараж Казахстан»:
ячейка H353 (START_DATE) первого паспорта содержит старую
фиксированную дату, а не формулу. **По одной ВОМ фактическую
дату начала новой отгрузки определить нельзя.**
Существующий STOP остаётся до появления подтверждённого
источника текущей даты. Автоматически переносить H353 нельзя;
в этом PR дата не выдумывается и рабочий реестр не меняется.

## Приёмка на Windows одним заданием

1. Интегрировать точный commit данной ветки в последние локальные
исходники EXE `1.0.0-RC3-sources-test`, сохранив возможные
более новые локальные исправления Word/Excel/PDF.
2. Выполнить полный Windows-regression одним прогоном и проверку
GUI (отображение четырёх колонок, расчёт точки росы, два
температурных условия, новая структура кнопок).
3. «Гараж Казахстан» 11/2026, ВОМ с четырьмя марками:
из общего УЗК получается 8 шт. Не перезаписывать рабочий реестр.
4. Полная исходная ВОМ: 104 марки, 288 изделий, 15 822.14 кг,
1 021.644 м²; плановый УЗК 33 шт. Повторить проверки.
5. Проверить в копиях Word, Excel и единый PDF, отказ
от подтверждения, SHA, recovery. Сначала открывать только
учебные результаты с явно маркированными тестовыми сведениями.
6. Проверить, что для нового паспорта с неподтверждённой
START_DATE отображается конкретная причина STOP; не заменять
её устаревшей датой и не выдавать официальный паспорт.
7. Только после полного PASS собрать новый ОТДЕЛЬНЫЙ onedir EXE
в `C:\VZMK-Passport\1.0.0-RC3-screen-test`, старые сборки
не заменять и новые ярлыки на рабочем столе не плодить.

До Native Windows Office+GUI E2E и EXE проверки статус этого PR
только **Code verified / Windows not run / Release NO_GO**.
