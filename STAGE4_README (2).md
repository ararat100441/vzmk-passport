# Этап 4 — DEV справочник профилей

Запуск просмотра: `Запустить Этап 4.cmd`. Обычный поиск работает по локальным данным без интернета.
Файл: `DEV/Справочники/Профили.xlsx`. Все размеры — мм. Production не используется.

CLI: установленный Python 3.12 (тот же, что для принятых этапов):

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B stage4.py build
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B stage4.py lookup "I 35Б1"
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B stage4.py lookup "35Б1" --standard "ГОСТ 26020-83"
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B stage4.py counts
```

Используются только два принятых audit snapshots. Manifest hashes закреплены в `profiles_stage4/offline.py`.
Build повторно проверяет hash evidence, XLS origins, cached HTML group JSON и точные numeric `sort` values.
Нет сетевого обновления. Python и Excel renderer блокируют сетевые обращения.
Для rebuild нужны offline Python `xlrd`, `lxml`, `openpyxl` и bundled Node/@oai/artifact-tool.
Junction `profiles_stage4/node_modules` указывает на bundled runtime и не содержит копий зависимостей.

Identity = нормализованный ключ + НД. Исходное обозначение не меняется.
Уголки имеют ключ `L100×8` / `L125×80×7`; исходный номер KM-KMD хранится отдельно в provenance.
У круглых труб точный ключ строится из numeric D/s: округлённое display остаётся в колонке Профиль и raw.
Поиск `Гнз 80х40х4` / `80x40x4` / `80×40×4` эквивалентен.
Не заданный НД не заменяет явно запрошенный НД. Серии/буквы не удаляются.
Ведущие нули серии сохраняются; у неизвестных ручных названий сохраняются границы слов.

Совпадающая identity объединяется в одну строку с provenance всех raw records, включая дубль 1420×20.
Различия типа или основных размеров h/b/b2/s/t/D создают BLOCKING конфликт: lookup возвращает CONFLICT,
canonical geometry остаётся пустой до явного решения. Расхождения только R/r, площади, массы и справочных
показателей — NON_BLOCKING: согласованные основные размеры доступны, спорные поля явно unresolved и исключены
из canonical values. Обе версии остаются в provenance и на листе «Конфликты» с классификацией.
Статус «СОГЛАСОВАНО_С_ЗАМЕЧАНИЯМИ» и примечание показывают справочное расхождение;
пустой R/r сам по себе конфликтом или ошибкой не является. Ничья версия не исправляется молча.
По разным НД сравниваются основные размеры. При эквивалентных размерах возвращаются все provenance/candidates;
различающийся R/r в объединённом ответе явно unresolved. Предпочтение никогда не разрешает конфликт внутри НД.

`profiles.catalog.json` содержит все исходные/parsed values, координаты и provenance.
`profiles.user.json` — авторитетное пользовательское состояние: ручные записи, предпочтения, явные решения.
`profiles.build.json` связывает SHA workbook/catalog/user state. Excel — читаемое представление.
Пользовательские изменения выполняются через API/CLI, а не непосредственным редактированием Excel/JSON.
При внешнем редактировании service останавливается до проверки; rebuild не перезаписывает изменённые файлы.
Каждая запись пользователя сохраняется при rebuild. Backup предыдущей полной generation находится в `backups/`.
Перед заменой создаются временные файлы, XLSX reopen проверяет все значения/типы. Preflight запоминает SHA
всех четырёх файлов, включая profiles.build.json. Непосредственно перед backup/commit Windows handles запрещают
внешнюю запись и удаление; проверяются те же четыре SHA. Изменение во время render вызывает STOP без замены.
Backup содержит проверенную согласованную previous generation. Commit и rollback переименовывают файлы через
собственные DELETE-capable handles с ReplaceIfExists=False. Даже внешний файл, созданный в кратком промежутке
между переименованиями, не перезаписывается: commit останавливается, собственные изменения откатываются.
При таком внешнем создании прежняя generation сохранена в backup; внешний файл требует отдельной проверки.
При обычной ошибке render/write/commit предыдущая generation остаётся рабочей. Writer lock дополнительно
сериализует операции самого service; Windows handles защищают от других приложений.

Ручное добавление: UTF-8 JSON с `profile`, `family`, `standard`, `geometry`, `note`.
Типы: Двутавр, Швеллер, Гнутый швеллер, Уголок равнополочный, Уголок неравнополочный,
Квадратный профиль, Прямоугольный профиль, Круглая труба.

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B stage4.py manual-add manual.json
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B stage4.py preference "35Б1" "ГОСТ Р 57837-2017" --basis "Решение пользователя"
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -B stage4.py resolve CF-... B-8510-86:47 --reason "Явное решение пользователя"
```

Resolve требует реальный Conflict ID и Record ID из provenance, сохраняет fingerprint всех вариантов и причину.
Изменение evidence делает прежнее решение неприменимым. Ручная запись не получает УЗК автоматически.
Отдельное подтверждение ручного двутавра: `confirm-manual-uzk USER-... --basis "Подтверждённое правило"`.

Правило ДВУТАВР_ПРОКАТНЫЙ_1: для одного изделия стенка `(h-2*t) × s`, полки `(2*b) × t`.
Решение пользователя 07.10.2026 добавляет три правила с назначениями в `profiles.user.json/uzk_approvals`:
ШВЕЛЛЕР_16П_1 только для 16П + ГОСТ 8240-97: `h × s`, `(2*b) × t`;
ГНУТЫЙ_ШВЕЛЛЕР_1 для отдельно подтверждённой ручной identity: `2*(h+b) × t`;
ЗАМКНУТЫЙ_ПРОФИЛЬ_1 для принятых квадратных/прямоугольных ГОСТ 30245-2003: `2*(h+b) × t`.
Новые ручные записи без подтверждённого КМД не получают правило из семейного назначения.
Подтверждённые ручные записи хранят КМД references и исходное обозначение; rebuild сохраняет их и назначения.
`Гн.[140X60X4` нормализуется с сохранением открытого типа; `Гн.[]120х3` — в закрытый 120×120×3.
Только при отсутствии точного ключа leading `[` может ссылаться на единственную существующую identity
прокатного швеллера. Несколько кандидатов/другой тип дают AMBIGUOUS; произвольные скобки не удаляются.
Одинаковая толщина внутри одного профиля объединяет длины. Количество изделий и другие марки не учитываются.
S < 12 → 5 МГц / 70°; S >= 12 → 2.5 МГц / 65°. Остальные назначения: НЕ НАСТРОЕНО.

ГОСТ 8639/8645, ТУ, специальные/«Вне ГОСТ», detail geometry с несколькими НД и дополнительные category rows не импортируются.
Stage 1–3 не вызываются из Stage 4. УЗК.xlsm, паспорт, Word/PDF, Stage 3 Apply и Stage 5 не используются.
